# P4924 [1007] 魔法少女小Scarlet

## 题目核心

题目维护一个 \(n\times n\) 的矩阵，初始按照从左到右、从上到下的顺序填入：

```text
1  2  3
4  5  6
7  8  9
```

每次操作给出：

- `(x, y)`：旋转中心
- `r`：旋转半径
- `z`：旋转方向

需要将以 `(x,y)` 为中心、边长为 `2r+1` 的正方形区域旋转 90°。

---

## 最重要的理解：不要死背旋转公式

这道题最开始最难理解的是矩阵旋转后的坐标变化。

真正应该理解的是：

> **先减去旋转中心，得到相对坐标；进行旋转；最后再把旋转中心加回来。**

假设旋转中心是：

```text
(x, y)
```

某个位置是：

```text
(i, j)
```

那么它相对于中心的位置就是：

```text
(i - x, j - y)
```

---

## 顺时针旋转

先记住方向变化：

```text
上 → 右
右 → 下
下 → 左
左 → 上
```

如果相对坐标记作：

```text
(a, b)
```

那么顺时针旋转 90° 后：

```text
(a, b) → (b, -a)
```

例如：

```text
(-1, 0)
```

表示在中心正上方。

顺时针旋转后：

```text
(0, 1)
```

正好变成中心右边。

所以理解矩阵旋转时，不应该直接背一长串 `x+y-j` 之类的公式，而应该从“相对于中心的位置发生了什么变化”推出来。

## 本题暴露出的错误

### 1. 初始化错误

最开始写成了：

```java
a[i][j] = i * j;
```

这样得到的是：

```text
1 2 3
2 4 6
3 6 9
```

而题目要求：

```text
1 2 3
4 5 6
7 8 9
```

后来改成使用 `count` 从 1 开始递增。

---

### 2. 旋转公式只考虑了 `x == y` 的特殊情况

最开始使用类似：

```java
temp[j][2 * x - i]
```

这样的公式。

当旋转中心满足：

```text
x == y
```

时有些样例可能碰巧正确，因此错误比较隐蔽。

但是当：

```text
x != y
```

时就会暴露问题。

这说明调试坐标题时不能只测试对称情况。

---

## 一个很重要的调试经验

这题顺便学会了 VS Code 的断点调试。

调试算法题不是不停按 F10，而应该：

```text
先预测正确值
        ↓
单步执行
        ↓
查看实际值
        ↓
比较“预期值”和“实际值”
        ↓
定位第一处不一致
```

例如旋转中心不要总测试：

```text
(2,2)
```

而应该刻意测试：

```text
(2,3)
```

这样才能暴露把 `x` 和 `y` 混用的问题。

对于二维数组，可以重点观察：

```text
i
j
x
y
a[i][j]
temp[...][...]
```

## 易错点

1. `x` 表示行，`y` 表示列，不要混淆。
2. 顺时针和逆时针的坐标变换方向容易写反。
3. 不能只拿 `x == y` 的情况测试。
4. 旋转过程中要使用旋转前的数据，不能让已经修改的数据影响后续位置。
5. 二维数组下标范围要特别注意。
6. 初始化矩阵时应该连续编号，而不是使用 `i * j`。

---

## 复杂度

当前模拟方法主要对旋转区域进行处理，并维护辅助矩阵。

如果每次操作后复制整个 \(n\times n\) 矩阵，则单次还会产生：

\[
O(n^2)
\]

的复制开销。

在当前题目数据范围下该实现已经通过评测，但以后遇到更大的数据范围时，可以考虑只同步发生变化的区域。

---

## 本题最大的收获

这道题最大的收获不是记住某个矩阵旋转公式，而是理解：

> **复杂的坐标公式，往往可以通过“先变成相对坐标 → 做变换 → 再恢复原坐标”推导出来。**

以后遇到旋转、平移、中心对称等二维坐标问题，可以优先从这个角度思考。
