# P1098 字符串的展开 —— 易错点总结

这道题算法本身并不复杂，真正的难点在于：

> **条件很多、分类很多、边界很多。**

样例通过并不代表所有情况都已经覆盖。做这类字符串模拟题时，需要重点检查分类是否完整、非法情况如何处理，以及字符串下标是否越界。

---

## 1. `p1 = 2` 时不要漏掉数字

一开始容易写成：

```java
else if(p1 == 2){
    if(ischar){
        ...
    }
}
```

这样只处理了字母。

如果左右两边是数字，例如：

```text
1-5
```

当 `p1 = 2` 时，数字虽然不存在“转大写”，但仍然应该正常展开：

```text
12345
```

### 正确分类

| 类型 | `p1 = 1` | `p1 = 2` | `p1 = 3` |
|------|----------|----------|----------|
| 字母 | 小写 | 大写 | `*` |
| 数字 | 原数字 | 原数字 | `*` |

### 经验

遇到参数较多、分类较多的模拟题，可以先画一个分类表。

这样比直接一边读题一边写大量 `if-else` 更不容易遗漏情况。

---

## 2. 默认行为应该先设置为“保持原样”

一开始写：

```java
String s = "";
```

存在一个问题：

如果当前 `-` 不满足展开条件，它就可能被直接删除。

例如：

```text
1-a
```

数字和字母不是同一类型，不能展开。

正确结果应该仍然是：

```text
1-a
```

而不是：

```text
1a
```

因此更好的写法是：

```java
String s = "-";
```

先假设这个减号不能展开：

```java
String s = "-";

if((ischar || isnum) && m > n){
    s = "";
    // 进行展开
}
```

### 经验

模拟题中一个非常实用的思想：

> **先设置默认行为，再处理满足特殊条件的情况。**

也就是：

```text
默认保持原样
    ↓
确认满足条件
    ↓
再修改
```

这种写法往往比不断增加 `else` 更安全。

---

## 3. 出现 `i - 1`、`i + 1` 时必须检查边界

代码中有：

```java
char n = line.charAt(i - 1);
char m = line.charAt(i + 1);
```

如果字符串为：

```text
-abc
```

此时：

```java
i = 0
i - 1 = -1
```

调用：

```java
line.charAt(-1);
```

就会发生：

```text
StringIndexOutOfBoundsException
```

在线评测中表现为：

```text
Runtime Error（RE）
```

因此访问左右字符之前必须检查：

```java
if(i == 0){
    pos = i + 1;
    continue;
}

if(i == line.length() - 1){
    break;
}
```

### 经验

以后代码中只要看到：

```java
a[i - 1]
a[i + 1]

s.charAt(i - 1)
s.charAt(i + 1)
```

就应该条件反射地想到：

> **边界会不会越界？**

这在 CSP、蓝桥杯的模拟题中尤其重要。

---

## 4. `indexOf()` 可以指定开始查找的位置

可以写：

```java
line.indexOf("-", pos);
```

表示：

> 从下标 `pos` 开始向后寻找 `"-"`。

如果找到，返回第一次出现的位置。

如果找不到：

```java
-1
```

例如：

```java
int i = line.indexOf("-", pos);

if(i == -1){
    break;
}
```

需要注意：

常用的 `String.indexOf()` 可以指定起始位置，但不能像区间 `[start, end]` 一样直接限制完整搜索范围。

## 5. `char` 参与算术运算后会变成 `int`

例如：

```java
char n = 'a';

n + 1
```

结果类型不是 `char`，而是：

```text
int
```

因此如果希望得到下一个字符，需要强制转换：

```java
(char)(n + 1)
```

P1098 中：

```java
s += (char)(n + q);
```

就是通过字符编码得到中间字符。

例如：

```text
'a' + 1 → 98
(char)98 → 'b'
```

### 常用规律

```text
char + int  → int
char - char → int
```

所以：

```java
'b' - 'a'
```

结果是：

```text
1
```

---

## 6. `String` 可以直接与 `char` 拼接

下面写法没有问题：

```java
String s = "";
char c = 'a';

s += c;
```

结果：

```text
a
```

因为：

```text
String + char → String
```

但是：

```java
'a' + 'b'
```

不同。

两个 `char` 进行的是数值运算：

```text
97 + 98 = 195
```

所以要记住：

```text
String + char → String
char + String → String

char + char   → int
```

如果一定要把两个字符拼成字符串，可以：

```java
String s = "" + a + b;
```

---

## 7. 小写字母转大写

Java 可以直接使用：

```java
Character.toUpperCase(c);
```

例如：

```java
char c = 'b';

char upper = Character.toUpperCase(c);
```

得到：

```text
B
```

P1098 中可以写：

```java
s += Character.toUpperCase((char)(n + q));
```

这样比自己计算：

```java
(char)(c - 'a' + 'A')
```

更加直观，也不容易写错。

---

# 本题真正值得记住的经验

P1098 最重要的收获不是某一个 Java API，而是字符串模拟题的检查方法。

样例通过以后，主动检查：

1. 每一个参数的所有取值是否都处理了；
2. 字母、数字等不同输入类型是否都覆盖了；
3. 不满足条件时，是删除、修改还是保持原样；
4. `i - 1`、`i + 1` 是否可能越界；
5. 循环中的位置变量是否一定会向前移动，避免死循环；
6. 多个条件组合后是否还有遗漏情况。

可以记成一句话：

> **默认保持原样，合法后再修改；看到左右下标先检查边界；样例通过后主动检查分类组合。**

这类能力对于 CSP 和蓝桥杯中的字符串模拟、过程模拟题非常重要。
